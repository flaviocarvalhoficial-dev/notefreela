# SKILL 4 — User Flow & Process Clarity Evaluator

Evaluation of User Flows and Process Clarity in Apps and SaaS

---

# SKILL OBJECTIVE

Evaluate whether the **user flows of the application are clear, logical, and efficient**, allowing users to complete their main tasks **with minimal friction and effort**.

This skill analyzes:

* flow clarity
* logical sequence of actions
* ease of navigation between steps
* number of steps required
* friction points in the process

It answers the core question:

> **Can users complete their tasks in a simple and logical way within the app?**

---

# USAGE CONTEXT

Use this skill when:

* the app has **defined user flows**
* a **functional MVP** already exists
* the main user tasks have been implemented
* you want to validate whether processes are truly efficient

Examples of flows to evaluate:

* user registration
* onboarding
* creating an item (task, project, client, etc.)
* generating reports
* submitting information
* payment or subscription flow

---

# REQUIRED INPUT

Before starting the evaluation, provide:

**1 — App name**

**2 — Main application flows**

**3 — Steps required to complete each flow**

**4 — Screenshots or descriptions of the involved screens**

**5 — Final objective of each flow**

---

# STEP 1 — IDENTIFY THE PRIMARY FLOW

Identify the **core flow of the application**.

Questions:

* What is the main task the user must perform?
* Which flow represents the main value of the product?

Example:

CRM
→ create lead → move in pipeline → register activity

Task management
→ create task → define status → track progress

Scoring:

| Flow clarity   | Score |
| -------------- | ----- |
| Confusing      | 1     |
| Poorly defined | 2     |
| Acceptable     | 3     |
| Clear          | 4     |
| Very clear     | 5     |

---

# STEP 2 — LOGICAL SEQUENCE

Evaluate whether the steps follow a **logical order**.

Questions:

* Do the steps make sense?
* Is the order of actions natural?
* Does the user need to go back or redo actions frequently?

Scoring:

| Flow logic     | Score |
| -------------- | ----- |
| Disorganized   | 1     |
| Weak logic     | 2     |
| Moderate       | 3     |
| Logical        | 4     |
| Highly logical | 5     |

---

# STEP 3 — NUMBER OF STEPS

Evaluate whether the flow has **an optimal number of steps**.

Questions:

* Are there unnecessary steps?
* Could the flow be shorter?
* Are there redundant stages?

Scoring:

| Flow efficiency  | Score |
| ---------------- | ----- |
| Very long        | 1     |
| Long             | 2     |
| Acceptable       | 3     |
| Lean             | 4     |
| Highly optimized | 5     |

---

# STEP 4 — NAVIGATION EASE

Evaluate whether users can navigate through the flow easily.

Questions:

* Is it easy to move forward and backward?
* Does the user understand where they are in the flow?
* Are there progress indicators?

Scoring:

| Navigation | Score |
| ---------- | ----- |
| Confusing  | 1     |
| Difficult  | 2     |
| Moderate   | 3     |
| Good       | 4     |
| Excellent  | 5     |

---

# STEP 5 — FRICTION POINTS

Identify obstacles in the process.

Questions:

* Are there points where users might get stuck?
* Are there complex fields or difficult decisions?
* Are there unnecessary interruptions?

Scoring:

| Friction  | Score |
| --------- | ----- |
| Very high | 1     |
| High      | 2     |
| Moderate  | 3     |
| Low       | 4     |
| Very low  | 5     |

---

# STEP 6 — FLOW COMPLETION

Evaluate whether users can **finish the process easily**.

Questions:

* Does the user know when the flow is complete?
* Is there clear feedback for completion?
* Does the system confirm the action?

Scoring:

| Completion clarity | Score |
| ------------------ | ----- |
| Confusing          | 1     |
| Unclear            | 2     |
| Acceptable         | 3     |
| Clear              | 4     |
| Very clear         | 5     |

---

# FINAL SCORE CALCULATION

Add all scores together.

Maximum score: **30**

---

# INTERPRETATION

| Score | Diagnosis              |
| ----- | ---------------------- |
| 0–10  | Problematic flows      |
| 11–18 | Acceptable flows       |
| 19–24 | Well-structured flows  |
| 25–30 | Highly efficient flows |

---

# FINAL DIAGNOSIS

After scoring, generate:

**1 — Summary map of the analyzed flow**

**2 — Problematic stages**

**3 — Redundant steps**

**4 — Friction points**

**5 — Strengths of the flow**

**6 — Optimization recommendations**

---

# FINAL RESULT

Classification:

❌ Problematic flow
⚠️ Acceptable flow
✅ Efficient flow
🚀 Highly optimized flow

---

# CORE PRINCIPLE

> A good product is not only functional — it naturally guides the user to the desired outcome.

Efficient flows:

* reduce clicks
* avoid confusion
* increase speed of use
* improve retention

This skill ensures that **processes within the app are natural, fast, and frictionless**.
